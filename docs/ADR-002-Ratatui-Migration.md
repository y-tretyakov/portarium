# ADR-002: Миграция TUI с OpenTUI на Ratatui

**Статус:** Accepted  
**Дата:** 22 июля 2026  
**Автор:** Главный Архитектор  
**Версия:** 1.0

## 1. Контекст

Текущий Terminal UI построен на **OpenTUI** (Bun + React-подобная модель).  
Это создаёт следующие проблемы:
- Зависимость от внешнего рантайма (Bun)
- Дублирование логики с Rust-бэкендом
- Сложность поддержки и отладки
- Два разных стека технологий в одном проекте
- Более медленный запуск и больший размер дистрибутива

## 2. Проблема

Нужно получить **нативный, быстрый, полностью Rust-based** Terminal UI, который:
- Использует `portarium-core`
- Имеет единую кодовую базу с Desktop-версией
- Сохраняет (и улучшает) текущий UX (клавиатурное управление, 4 страницы дашборда)

## 3. Решение

**Переписать TUI на Ratatui + crossterm**.

### Преимущества Ratatui

- Полностью на Rust (один бинарник)
- Высокая производительность
- Зрелая экосистема (widgets, layout, events)
- Отличная поддержка кроссплатформенности
- Легко тестировать (headless режим)
- Соответствует духу проекта (blazing-fast)

### План миграции

1. Создать crate `portarium-tui`
2. Реализовать базовый event loop (`AppState`, `Event` enum)
3. Перенести экраны по приоритету:
   - Ports (основной список)
   - Dashboard
   - Services
   - Logs
4. Сохранить все keybindings
5. Добавить mouse support (опционально)
6. Удалить `src-tui/` после успешной миграции

## 4. Альтернативы

| Вариант              | Плюсы                    | Минусы                          | Выбор |
|----------------------|--------------------------|----------------------------------|-------|
| Оставить OpenTUI     | Быстро                   | Дублирование, техдолг           | Нет   |
| Ratatui              | Производительность, чистота | Нужно писать UI заново         | **Да** |
| Textual (Python)     | Богатый UI               | Не Rust, отдельный рантайм      | Нет   |
| Iced / Druid         | GUI-like                 | Overkill для TUI                | Нет   |

## 5. Последствия

**Положительные:**
- Один бинарник для TUI
- Полная интеграция с `portarium-core`
- Лучшая производительность
- Проще CI/CD и дистрибуция
- Улучшенная расширяемость

**Отрицательные:**
- Временные затраты на переписывание UI
- Нужно внимательно перенести UX

**Риски:**
- Потеря некоторых визуальных фич OpenTUI → компенсировать качеством Ratatui

## 6. Критерии успеха

- Все ключевые keybindings работают
- Производительность не хуже текущей
- `npx portarium` (или аналог) продолжает работать через совместимость
- Тесты на core используются в TUI
